## LLM ratings for all Studio practice questions (21 October 2026)

Every practice question in Studio requires an individual LLM reasoning score and task-specific rationale on the existing cognitive-demand scale below. Exclude teaching examples and guided practice. Initial import authoring must supply the raw integer score, derived band and rationale even when no optional classification catalogue is configured; fallback scores are not assessments. The existing independent content review checks rating consistency and substantive corrections in the same pass. Import completion requires complete verified rating coverage.

`classification.assessment` records the actual model, assessment time, rubric version, assessed-task hash and model-output evidence path. The hash covers canonical mathematical content, answers and diagrams, ignoring local layout and node IDs. Task changes require reassessment; layout changes do not. Pure whole-question renumbering may reuse an assessment with its original binding retained as `originalTaskHash`; the actual model and time stay unchanged. This provenance grants no source or mathematical-review acceptance. Reuse historical model output only when its task, score and rationale match and its call log establishes the actual model and time; never invent historical provenance.

Scores describe estimated cognitive demand on a prepared student who has been taught the relevant booklet methods. They are not empirical success rates or measured item difficulties. The cognitive-demand rubric follows the locally available MathsDatabase `prompts/difficulty-rating-prompt.md`: direct application; routine linked procedures; non-trivial connections or reframing; decisive unsignposted insight. Assess the student-facing task before using its solution to detect hidden demand. Count decisions, representation changes and interpretation, not pages, number of repeated parts, arithmetic bulk or solution length. Account for scaffolding actually present in the question. Rate a multipart task by the demand required to complete it, rather than averaging away its hardest essential part. Fractional numbers alone do not create a higher band. Scores within a band are judgement estimates, not claims of one-point measurement precision.

## Source-guided classification (12 September 2026)

Identify each question's main assessed skill using the booklet's stage, topic, exercise heading and relevant teaching examples together with the student-facing task. Use this teaching context to distinguish the intended assessment from supporting calculations or incidental skills. Do not classify a question from its wording or solution alone. Record the context and rationale supporting the primary skill in the assessment register; assign secondary skills only when directly assessed. If the context is missing or conflicts with the task, flag the classification for review rather than guessing.

Use the accepted source booklet's stage/course, topic, exercise purpose and relevant teaching examples to select the main assessed skill. Check the actual question and required response; a booklet title alone is not enough. Keep genuine cross-topic tasks, with an explicit reason. Supporting prerequisites belong in teaching mappings, not library secondary tags, because either tag can place a question in a topic filter.

New import-project-bank.mjs publications require sourceContext evidence tied to the complete current project hash, with syllabus courseIds/topicIds and inspected evidenceBlockIds. Every question needs mappingNote; out-of-scope skills require sourceContextException. Missing, stale or conflicting evidence stops publication for review. Completed import receipts remain historical evidence. Individual promotion preserves an explicit question classification over teaching-map defaults.
