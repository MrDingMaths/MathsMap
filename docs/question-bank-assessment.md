# Question-bank assessment

## LLM ratings for all Studio practice questions (21 October 2026)

Every practice question in Studio requires an individual LLM reasoning score and task-specific rationale on the existing cognitive-demand scale below. Exclude teaching examples and guided practice. Initial import authoring must supply the raw integer score, derived band and rationale even when no optional classification catalogue is configured; fallback scores are not assessments. The existing independent content review checks rating consistency and substantive corrections in the same pass. Import completion requires complete verified rating coverage.

`classification.assessment` records the actual model, assessment time, rubric version, assessed-task hash and model-output evidence path. The hash covers canonical mathematical content, answers and diagrams, ignoring local layout and node IDs. Task changes require reassessment; layout changes do not. Pure whole-question renumbering may reuse an assessment with its original binding retained as `originalTaskHash`; the actual model and time stay unchanged. This provenance grants no source or mathematical-review acceptance. Reuse historical model output only when its task, score and rationale match and its call log establishes the actual model and time; never invent historical provenance.

Inventory with `node scripts/booklet/rate-studio-questions.mjs`; add `--apply` to assess missing, default, stale and unverified ratings, or `--project ID` to scope it. The backfill resumes from `.booklet-work/reasoning-ratings/`, reuses valid assessments and reports explicit blockers. Workers use GPT-6.1 Sol low, read-only access and the canonical booklet worker pool. On Windows, launch the applying command with the authorised host permissions from the first attempt. Rating saves use the bank transaction helpers, expected project/task/bank revisions and metadata-only updates, preserving content, skills, order, layouts and pinned content. A locally amended task retains its own rating rather than overwriting a different canonical bank question. No PDF export is needed for this metadata maintenance.

The full applying command also covers selectable practice records in Studio's Question bank tab, including those not placed in any booklet. `node scripts/booklet/rate-bank-questions.mjs [--apply]` inventories or resumes that phase independently. Theory reviews remain excluded. The bank phase retains existing IDs, classifications, content and sync baselines and never creates duplicate questions.

Original raster assets are attached directly to rating calls. For essential external hints, `--evidence FILE` accepts `{sources:[{url,...sourceData}]}`; only questions referencing that URL receive its supplied source data. The caller binds task hashes and maps short bank response IDs back to existing records. Valid individual responses from an interrupted or malformed batch are recovered from the original input, model output and metrics; mismatched identities are never accepted.

The September 2026 Linear Relationships assessment replaces the original builder's category defaults with individual readings of all 180 bank records. Ten source-labelled Review questions remain available to pinned booklets and teaching modules, but have `libraryRole: "theory-review"` and are excluded from the practice manifest, filters and bank assembly candidates. Three existing draft continuation records also remain unlisted, leaving 167 selectable questions. They are not deleted from the accepted booklet. Guided practice and Identify tasks are not excluded merely because they occur near theory.

Scores describe estimated cognitive demand on a prepared student who has been taught the relevant booklet methods. They are not empirical success rates or measured item difficulties. The existing 0–100 scale is retained: Foundation 0–24, Development 25–49, Mastery 50–79, Challenge 80–100. No distribution or quota is imposed, and equal-demand questions can share a score.

The cognitive-demand rubric follows the locally available MathsDatabase `prompts/difficulty-rating-prompt.md`: direct application; routine linked procedures; non-trivial connections or reframing; decisive unsignposted insight. Assess the student-facing task before using its solution to detect hidden demand. Count decisions, representation changes and interpretation, not pages, number of repeated parts, arithmetic bulk or solution length. Account for scaffolding actually present in the question. Rate a multipart task by the demand required to complete it, rather than averaging away its hardest essential part. Fractional numbers alone do not create a higher band. Scores within a band are judgement estimates, not claims of one-point measurement precision.

Evidence includes current question prompts, tables and representation panels, diagram models/descriptions, supplied answers, shared continuation groups and the accepted booklet's teaching sequence (recorded in the Linear Relationships atomisation audit). The assessment retains the table-change/intercept and graphical-solving methods. It does not rewrite questions or answers. The assessed content hash, before/after classification and rationale are recorded in `linear-bank-assessment-register.json`; edited content needs reassessment rather than automatic reuse of its old score.

The library classification describes the main task and other directly assessed skills. Detailed node teaching mappings remain unchanged and can include supporting algebra. The original transfer promoted `equations-from-formulas` to the primary skill on whole pattern pages, including questions with no inverse calculation. Because topic filters use both primary and secondary skills, that made pattern tasks appear under Equations. The correction removes the incidental formula-solving tag from pattern, table and contextual linear-model tasks. Explicit algebra-versus-graph comparison tasks retain it. Given-rule questions use `apply-pattern-equation`, not `pattern-to-equation`.


New theory reviews are blocked from individual question promotion and can be saved inline in teaching modules. New publications require individual assessments rather than ratings inferred from page numbers. Current owner saves follow `booklet-bank-auto-sync.md`; the completed Linear migration tool is retired.

## Source-guided classification (12 September 2026)

Identify each question's main assessed skill using the booklet's stage, topic, exercise heading and relevant teaching examples together with the student-facing task. Use this teaching context to distinguish the intended assessment from supporting calculations or incidental skills. Do not classify a question from its wording or solution alone. Record the context and rationale supporting the primary skill in the assessment register; assign secondary skills only when directly assessed. If the context is missing or conflicts with the task, flag the classification for review rather than guessing.

Use the accepted source booklet's stage/course, topic, exercise purpose and relevant teaching examples to select the main assessed skill. Check the actual question and required response; a booklet title alone is not enough. Keep genuine cross-topic tasks, with an explicit reason. Supporting prerequisites belong in teaching mappings, not library secondary tags, because either tag can place a question in a topic filter.

New import-project-bank.mjs publications require sourceContext evidence tied to the complete current project hash, with syllabus courseIds/topicIds and inspected evidenceBlockIds. Every question needs mappingNote; out-of-scope skills require sourceContextException. Missing, stale or conflicting evidence stops publication for review. Completed import receipts remain historical evidence. Individual promotion preserves an explicit question classification over teaching-map defaults.

The Linear Relationships correction register is booklets/provenance/linear-relationships-v1/source-classification-review.json. It reviews all seven records tagged find-rule-from-table, including the adapted two-part record. Tables requiring linear equations use find-equation-from-table; graph/coordinate relationships use the relevant Stage 4 representation skill. Genuine unit-conversion and geometric tasks elsewhere retain their directly assessed skills. Questions, solutions, teaching mappings, difficulty scores and layouts are unchanged.
