# Question references during authoring order changes

Run this only in the persistent Node authoring/import-review workflow, before export. Never run it on project load or in the renderer. Preserve the original source and stable owner/node IDs.

Resolve literal Question N and Qn references against the **before** project's actual `flowNumbers` and exercise/topic scope. The source candidate must retain source order before this binding: the legacy compact creation sorter can otherwise lose the original target identity. Set `questionOrder: source` before compact creation, then use the Node order planner. Printed question and answer labels already follow the renderer's numbering; this helper changes only bound reference digits in printable native question, inline/table and short/worked fields.

A resolved explicit reference joins its whole owners into an ordered unit, using the maximum of their existing verified LLM scores. Implicit relationships need a full source-bound exercise review including complete prompts, answers, examples, theory and necessary diagram meaning. That review must distinguish an inseparable result/scaffold unit from an order-only prerequisite or generic earlier method. Do not merge every method-support edge or infer independence from truncated digests. Preserve internal parts, meaningful source instructions and Challenge boundaries.

Archetype `practiceEvidenceIds` substantiate coverage or a scaffold in practice; they do not establish a prerequisite from every cited owner to every question in the cluster. `reviewedMethodSupport` validates those anchors and exposes recipient-specific candidates. Its `practiceSupportDecision` callback records the existing holistic review's reasoned `coverage-only` or `prerequisite` decision; unresolved candidates remain held. Own-question scaffolds stay inside their unchanged owner. Teaching/example/guided-practice anchors, native dependencies and literal-reference groups retain their existing checks. This adds no model review or external receipt requirement.

`resolveExerciseReferences` produces a pinned binding. `planScoreOrder` accepts it as `referenceResolution`; direct calls without one conservatively hold all recognised printed references, including Qn and top-level answer fields. `scoreOrderCandidate(..., {includeReferenceProof:true})` returns the candidate and a typed reference-number adaptation proof. The CLI includes this proof and flags assessments needing explicit existing-rating reuse. It never saves a live project.

Ranges, lists, decimal/page-qualified references, ambiguous or missing numbers, other sections, relative references and opaque HTML/native-code/math references hold for explicit resolution. The initial implementation conservatively holds the whole resolver application when any unresolved reference remains. It does not guess a target, parse arbitrary HTML, alter math numbers or rewrite provenance/IDs. Existing noncontiguous-unit holds remain.

Literal reference edits can change `reasoningTaskHash`. An old assessment must not silently remain current. `reuseReferenceNumberRating` replays the exact stable-target proof and requires an explicit coordinator callback accepting the existing verified LLM assessment. The approved verification cuts do not require a second numeric verdict for this mechanical change. Preserve the old score/model/date/evidence and history, record the task transition and never claim fresh inference. The caller must verify and update an exact matching local difficulty cache, or hold a conflicting cache. Preserve every bank link; supported SDK preview must prove no new bank publication, external database write or unrelated project write. Do not detach or recreate a linked question to pass this gate.

Challenge candidate transformation conservatively rejects unresolved printed question/answer references before moving or sorting anything. Finish the reviewed group/reference workflow first. Final publication still requires source/revision guards, current verified ratings, practice sufficiency, actual no-avoidable-split pagination and affected-page inspection. New or mathematically changed questions retain their initial independent combined review requirement.

Before numbered targets can be bound, `settings.questionOrder` must explicitly be `source`. Unset or legacy difficulty order holds because current counters may already have been rearranged by compact creation. This flag is a conservative necessary condition, not proof of original source identity. Do not flip it merely to suppress a hold: verify the retained original exercise and stable targets first. Math-formatted tokens such as `Question $11$` or `Q\(11\)` hold rather than silently escaping the reference detector.

A resolved reference group persists both semantic and pagination metadata: the dependent owner gains the stable target in `flow.dependsOn`, preserving every old dependency, and each predecessor in the ordered group gains `flow.keepWithNext: true`. The latter is what the existing production paginator consumes; `dependsOn` alone does not keep separate owners on one page. Both changes are included in the typed reference proof and exact replay/inverse. A reviewed false keep pin or internal forced page break holds instead of being overwritten. The group still needs actual fresh-page fit/handwriting checks; metadata cannot make an oversized group fit. No frontend change is needed.

Without a pinned resolution, any recognized printed reference holds ordering across the whole project, including target exercises in other sections. Printed teaching text and renderer-visible source-atom subtitles are scanned; unsupported teacher/atom bindings remain held. Provenance IDs and invisible source descriptions are excluded. Resolved holds likewise protect every section; source order is necessary but not proof of historical identity.
