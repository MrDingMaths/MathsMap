# Booklet bank and recipe schema

Source of truth for `booklets/bank/<bank>/**`, `booklets/recipes/*.json`, and the PDF
renderer that consumes them. The validator (`scripts/booklet/validate-bank.mjs`), the
transcription tasks and the renderer must agree with this document. **Unknown keys are
errors.**

This is a **second bank**, deliberately separate from the MathsMap skill atoms in
`public/content/{skillId}.json` ([content-schema.md](content-schema.md)):

| | MathsMap atoms | Booklet bank |
|---|---|---|
| Scope | one skill, always | booklet/exam style, may mix skills |
| Purpose | the app's per-skill practice and quizzes | printed booklets |
| Skill link | `skillId` — the file *is* the skill | `skills[]` + `primarySkill` — metadata only |
| Shape | `practice.{foundation,development,mastery}[]` | flat cards with `tier`, `parts[]`, `answer`, `marks` |

The link runs **one way only**: a booklet card names skills; nothing imports booklet cards
into `public/content/`. A recipe may pull from **both** banks — atoms for single-skill drill
sections, booklet cards for everything else.

The **shared rich-text format is identical** to content-schema.md and is not restated here:
`$…$` KaTeX inline maths (no display maths), `**bold**`, `[tikz]…[/tikz]` blocks, newline =
line break, `\$` for a literal dollar, every LaTeX backslash JSON-escaped. Both banks are
linted by the same `validateInlineText` / `validateTikz` in `scripts/lib/lint-math.mjs`.

## Directory layout

```text
booklets/bank/<bankSlug>/bank.json             header
booklets/bank/<bankSlug>/cards/<section>.json  { bank, section, cards: [...] }
booklets/bank/<bankSlug>/blocks/<section>.json { bank, section, blocks: [...] }
booklets/bank/<bankSlug>/figures/imageN.png    staged PNGs (booklets/**/media/ is gitignored)
booklets/bank/index.json                       generated by scripts/booklet/build-bank-index.mjs
booklets/recipes/<recipeSlug>.json
```

One file **per section**: the section is the unit of transcription (one agy task), of the
fidelity check, and of `validate-bank.mjs --only`. Per-card files would mean ~150 files; a
single per-booklet file would have parallel tasks fighting over one blob.

`figures/` rather than `media/` because `.gitignore` carries `booklets/**/media/` — the bank
must be self-contained in git.

### `bank.json`

```json
{
  "bank": "s5-trig-c-2",
  "title": "Non-Right-Angled Trigonometry",
  "course": "Mathematics Stage 5 Path",
  "sourceFile": "booklets/Stage 5/Trigonometry C 2_Non-Right-Angled Trigonometry.md",
  "sourceDocx": "booklets/Trigonometry C 2_Non-Right-Angled Trigonometry.docx",
  "sourceMediaDir": "booklets/Stage 5/media/Trigonometry C 2_Non-Right-Angled Trigonometry/media",
  "topicIds": ["t-s5p-trg-c"],
  "dotPointIds": ["dp-s5p-trg-c-2"],
  "sections": ["labelling-triangles", "sine-rule-sides", "..."]
}
```

`sections` is the printed order and must match the files present in `cards/` and `blocks/`.

## Card

```json
{
  "id": "sine-rule-sides-d4",
  "tier": "development",
  "skills": ["sine-rule", "angle-sum-triangle"],
  "primarySkill": "sine-rule",
  "structure": "side-after-angle-sum",
  "question_text": "Find the length of $x$, correct to $1$ decimal place.",
  "answer": "$7.9$ m",
  "solution_text": null,
  "scaffold": "$\\dfrac{x}{\\sin 52^{\\circ}} = \\dfrac{\\rule{1.2cm}{0.4pt}}{\\rule{1.2cm}{0.4pt}}$\n$x =$ {{blank}}",
  "figure": { "png": "figures/image29.png", "crop": { "l": 0, "t": 0, "r": 0.667, "b": 0 }, "widthCm": 4.0 },
  "columns": 3,
  "space": 6,
  "marks": 2,
  "calculator": true,
  "tags": ["angle-sum-first"],
  "source": { "kind": "hsc", "year": 2022, "course": "Standard 2", "band": 5 },
  "origin": { "file": "booklets/Stage 5/Trigonometry C 2_...md", "section": "Sine Rule for Sides", "tier": "development", "q": 4, "lines": [349, 366] },
  "parts": [
    { "label": "a", "question_text": "Find $\\angle ABC$.", "answer": "$95^{\\circ}$", "marks": 1, "space": 4 }
  ]
}
```

| key | required | notes |
|---|---|---|
| `id` | ✔ | `<sectionSlug>-<f\|d\|m\|g><n>` from the booklet's own numbering (`g` = generated, not transcribed). Unique across the bank. Recipes address it as `<alias>/<id>`. |
| `tier` | ✔ | `foundation` \| `development` \| `mastery` — the booklet's own placement. This is what class variants filter on. |
| `skills` | ✔ | non-empty; every id must exist in `data/skills.json`. Multi-skill is normal here. |
| `primarySkill` | ✔ | must be a member of `skills`. |
| `structure` | ✖ | kebab-case archetype slug (`isStructureSlug`). Warn-only against the primary skill's vocabulary — exam cards legitimately fall outside it. |
| `question_text` | ✔ | rich text. |
| `answer` | cond. | the **printed short answer** the current booklets show (`7.9 m`, `005^{\circ}`). Required on a partless card unless `solution_text` is present; required on each part likewise. A card with `parts` has **no** top-level `answer`. |
| `solution_text` | ✖ | full worked solution, house style (equals-aligned, final line is the answer). Left `null` by transcription; filled later by a solve lane. |
| `scaffold` | ✖ | working template printed under the stem in student variants — the booklet's `............` fills. Blanks: `{{blank}}` in prose, `\rule{1.2cm}{0.4pt}` inside `$…$`. |
| `figure` | ✖ | `{ png, crop?, widthCm? }`, see below. |
| `figures` | ✖ | The ADDITIONAL diagrams this item shows, beyond `figure`, in source order. A booklet cell sometimes carries a pair (a before/after, a plan and an elevation); without this they would be lost. Requires `figure`. |
| `columns` | ✖ | 1–4, cells per row for `parts`. Auto-derived when absent. |
| `space` | ✖ | integer working lines of answer space (1–20). Derived by the renderer when absent. |
| `marks` | ✖ | positive integer; rendered as `(2)`. |
| `calculator` | ✖ | boolean, default `true`. |
| `tags` | ✖ | kebab-case free vocabulary (`bearings`, `show-that`, `circle-segment`). |
| `source` | ✖ | `{ kind: "hsc", year, course, band? }` or `{ kind: "booklet" }` (default). Printed as a provenance tag. |
| `origin` | ✔ | `{ file, section, tier, q, lines: [start, end] }` — where it came from, so the fidelity check can pull the exact source slice. **Immutable**: set by the parser, never by a model. |
| `parts` | ✖ | lettered sub-questions, see below. |

### `figure`

```json
{ "png": "figures/image6.png", "crop": { "l": 0.391, "t": 0.031, "r": 0.395, "b": 0.574 }, "widthCm": 3.8 }
```

- `png` — path relative to the bank directory. Must exist.
- `crop` — fractional insets from each edge, `0 ≤ v < 1`, `l + r < 1`, `t + b < 1`. Same
  semantics as the docx `<a:srcRect>` these are extracted from (Word values are percent ×
  1000, so `l="39117"` → `0.39117`). Needed because 45 of this booklet's PNGs are composite
  strips shown as different crops in different cells; pandoc discarded the crop.
- `widthCm` — printed width in centimetres (the md's `{width="1.5in"}` × 2.54).

A `[tikz]` block inside `question_text` **supersedes** `figure`; the validator warns when both
are present, so replacing a PNG with a transcribed TikZ figure later is a one-field deletion.

### `parts`

Lettered sub-cells of one numbered question — never separate cards. Keys:
`label`, `question_text`, `answer`, `solution_text`, `scaffold`, `figure`, `figures`, `marks`, `space`.
`label` must run `a`, `b`, `c`, … in order with no gaps.

## Blocks

Everything in a booklet that is not a question: teaching boxes, review drills, worked
examples, cloze summaries, proofs. Blocks are **booklet-specific** — a Review box drills
exactly the prerequisites *this* booklet assumed — so they live per bank in
`blocks/<section>.json`, while cards are the reusable pool.

Envelope: `{ id, type, title?, tier?, columns?, origin }`, `id` = `<section>-<type>-<n>`.
`tier` is optional and lets a variant drop a block (proof boxes carry `tier: "mastery"`).

A **Cell** — used by every drill-style block — has the same shape as a part:
`{ label, question_text?, answer?, solution_text?, scaffold?, figure?, figures?, space? }`.

| `type` | payload | source in the Word booklet |
|---|---|---|
| `syllabus` | `{ outcome, points: [richtext] }` | the Syllabus Content section |
| `teach` | `{ body: richtext, formula?: richtext, figure? }` | untitled/definition boxes |
| `review` | `{ groups: [{ prompt, cells: [Cell] }] }` | `- **Review**` box (nested drill grids) |
| `identify` | `{ prompt, exemplars: [{ verdict: "yes"\|"no", figure?, text? }], cells: [Cell] }` | `- **Identify** …` box with ✔/✖ |
| `keyIdeas` | `{ items: [{ text }] }`, `text` carries `{{answer}}` blanks | `- **Key Ideas**` cloze box |
| `write` | `{ prompt?, cells: [Cell] }` | `- **Write** …` box |
| `example` | `{ question_text, figure?, solution_text }` | `- **Example**` box; solution always prints |
| `guided` | `{ prompt, cells: [Cell] }` | `- **Guided Practice**` box |
| `proof` | `{ figure?, steps: [{ prompt, working }] }` | `Proof of the …` boxes |
| `markdown` | `{ body: richtext }` | escape hatch for unclassified content — validator warns |

Box-label → type: Review→`review`, Identify→`identify`, Key Ideas→`keyIdeas`,
Write→`write`, Example→`example`, Guided Practice→`guided`, Proof→`proof`, anything
else→`teach`.

`{{answer}}` renders as a dotted blank in student variants and as the filled answer under
`--solutions`.

## Recipe

```json
{
  "slug": "s5-trig-c-2",
  "meta": {
    "course": "Mathematics Stage 5 Path",
    "title": "Non-Right-Angled Trigonometry",
    "book": 2,
    "description": "Apply the sine and cosine rules to any triangle and solve related problems",
    "version": "260830",
    "feedbackUrl": "https://MrDingMaths.com"
  },
  "banks": { "trig": "s5-trig-c-2" },
  "defaults": {
    "tiers": ["foundation", "development", "mastery"],
    "output": { "spaces": true, "solutions": false, "shortAnswers": false }
  },
  "variants": {
    "teacher":  { "output": { "spaces": false, "solutions": true, "shortAnswers": true } },
    "standard": {},
    "top":      { "tiers": ["development", "mastery"] },
    "support":  { "tiers": ["foundation", "development"], "output": { "shortAnswers": true } }
  },
  "sections": [
    {
      "title": "Sine Rule for Sides",
      "items": [
        { "block": "trig/sine-rule-sides-review-1" },
        { "block": "trig/sine-rule-sides-teach-1" },
        { "atoms": { "skill": "sine-rule", "tiers": ["foundation"], "structures": ["solve-sine-proportion"], "limit": 3 } },
        { "cards": { "bank": "trig", "section": "sine-rule-sides" } },
        { "cards": ["trig/cosine-rule-sides-m9"], "columns": 2 }
      ]
    }
  ]
}
```

An item is exactly one of:

- `{ "block": "<alias>/<blockId>" }`
- `{ "cards": ["<alias>/<cardId>", …] }` — explicit list, printed in the order given
- `{ "cards": { "bank": "<alias>", "section": "<slug>", "tiers"?: [...], "tags"?: [...] } }` — selector
- `{ "atoms": { "skill": "<skillId>", "tiers": [...], "structures"?: [...], "limit"?: n, "exclude"?: [i, …] } }`

Any item may carry `columns`.

The active variant's `tiers` filter applies to cards, atom pulls, and tiered blocks alike —
that is the whole mechanism for class variants. CLI flags override `output`.

**Atom pulls** resolve into card shape: `answer` is the last pure-maths line of the atom's
`solution_text` (the house style guarantees the final line is the answer), `skills` is
`[skill]`, `tier` is the atom's practice tier.

## Validation and tooling

```bash
npm run validate            # content + quizzes + booklet bank + recipes
npm run validate:booklet    # bank + recipes only
node scripts/booklet/validate-bank.mjs --bank s5-trig-c-2 --only sine-rule-sides
npm run bank:index          # regenerate booklets/bank/index.json
```

`validate-bank.mjs` exits 1 on errors, 2 on CLI misuse, and prints `⚠`/`✗` lines in the same
format as `scripts/validate.mjs`.
