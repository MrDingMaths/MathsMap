# Opt-in campaign render dependency scope

`content-campaign-render-dependencies-scoped-v1` is an explicit campaign policy. The default remains `content-campaign-render-dependencies-v2`; historical manifests, receipts and recorded configuration are never rewritten. Activation requires an immutable, hash-bound `content-campaign-scoped-render-code-review-v1` receipt from a different GPT-6.1 Sol Medium worker at Standard (`default`) service tier, accepting the exact files in `CAMPAIGN_SCOPED_RENDER_CODE_FILES`.

The scope retains the complete v2 import graph, including every inactive component's styles, import-time wiring, producer, cache server, CSS assets, installed KaTeX fonts, public TeX/wasm/fonts and lockfile. It projects only function bodies in `src/lib/booklet-pagination.js` and the private `validateSourceLongDescription` body in `campaign-sources.mjs`. Imports, signatures, module initialization and other source-helper functions stay bound. Pins bind the independently reviewed App route shell, two pagination consumers and projected module skeletons. The actual active skill, Theory, TikZ and shell import graph must remain disjoint from pagination; new pagination consumers and new source-parser imports reject. Changed pins require independent review before new scoped captures.

Use `withCampaignRendererContext(root, callback, {profile, activation})` for verification. Captures/finalization take `rendererDependencyProfile` and `rendererActivation`; omitted arguments retain v2. Campaign forwarding uses the same policy fields. Opted contexts verify activation, current dependencies and the canonical producer's live browser version, executable path and binary hash. Capture receipts additionally retain actual font/viewport environment, input, candidate, complete whole-field/block hashes and PNG hashes. Source identity or this dependency projection never grants pixel-inspection credit. Existing independent visual inspection gates remain required.

`activateScopedRendererPolicy` saves the explicit prospective campaign policy only after its exact-code review and live browser/context gates pass. The local ignored `capture-staged-diagrams.mjs` driver must read that policy with `campaignRendererOptions(readCampaign(...))` and map `{profile, activation}` to capture's `{rendererDependencyProfile: profile, rendererActivation: activation}`. Merely activating the ledger does not change an old driver's default capture arguments. Configure that driver only after independent code acceptance; historical receipts remain v2.

Fresh scoped captures can survive a local pagination or private source-parser body repair. Painting, CSS, fonts, producer, content and browser changes reject applicable evidence. Any change to the code accepted by the activation receipt requires a new independent exact-code review. Activation is not a browser upgrade exception.

`compareCampaignNonPaintingDependencyDelta` is a dependency comparison for complete original/current v2 manifests, requiring archived original/current source bytes hash-bound to changed rows. It rejects all additional changes, membership differences and unreviewed wiring. It is not wired to relabel historical receipts. In particular, this implementation changes renderer code itself, so existing v2 signatures remain stale; historical browser/renderer drift remains pending until an independently justified exact applicability transition or normal current capture and inspection. No Git HEAD reconstruction or automatic source-only acceptance is permitted.

Regression coverage uses a copied actual application graph and synthetic PNG fixtures with live browser probes. Those fixtures test guards and receipt preservation only; they do not establish production visual inspection or measured efficiency savings.
