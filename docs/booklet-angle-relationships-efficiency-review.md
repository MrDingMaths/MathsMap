# Angle Relationships import: speed and token-efficiency review

Reviewed 13 September 2026. Scope: completed Angle Relationships v1 run. The implemented workflow is described below; it does not modify booklet content, the renderer, acceptance contracts or model configuration.

## Evidence and measurement limits

Evidence: `.booklet-work/full-imports/angle-relationships-v1-20260912/semantic-packets/ledger.jsonl`, `run-receipt.json`, final-r77/r79/r84 review artifacts, and `scripts/booklet/semantic-workflow.mjs` / `token-efficient-prompts.mjs`.

- 79 source pages; 863 native diagram occurrences; 467 final physical pages across five editions. This geometry-heavy booklet is not a universal timing baseline.
- Ledger: 82 inventory calls (5 failures), 79 author calls (23 failures). Some failed attempts were salvaged locally; failure does not mean the entire call was repeated.
- Eighteen author failures were unknown inventory mappings for generated groups/headings. These are schema/identity errors, rather than difficult mathematics.
- Recorded usage: 5,006,300 input tokens, including 3,021,184 cached input tokens, and 1,107,561 output tokens. Cached input is a subset, not additional usage. Primary reviewer usage is excluded. Twenty-seven failed ledger records lack usage, so these figures are incomplete, not total billed usage.
- In `runSemanticPackets`, `reply.metrics` is available before validation, but the catch records only `error.metrics`. Validation/publication failures can therefore lose usage and duration. Fix this before claiming savings.
- Recorded model durations total 34,855,772 ms (about 9.68 call-hours); calls overlapped with configured concurrency 3. This is not elapsed wall time. The receipt contains older checkpoint totals and stale intermediate fields alongside final fields.
- Successful author records average approximately 47,354 prompt characters. The independent inventory contributes about 18,816; schema 5,893; DOCX supplement 5,839; diagram guidance 4,459; reconstruction contract 4,159; teaching context 3,194. These are character counts, not token counts, and exclude failed records without prompt statistics.
- Three final export generations exist: r77, r79, r84. Late repairs included label bounds, separately scaled answer overlays, and an answer-width override invalidated by a diagram-code hash change.
- The five final rasterisation/comparison passes total about 16.23 seconds. This excludes browser rendering, compilation and visual inspection; it does not establish their relative share of elapsed time.

## Priorities

1. **Validate the smallest answer width before bulk diagram authoring.** Exercise question, short and worked representations for each representative pattern. Check complete-label bounds after 10 pt calibration, angle regions, overlay alignment and source-hashed width overrides. Promote the label-bounds audit into the normal development gate. Keep mathematical and visual review separate. A reusable isolated-preview harness should validate the actual project/open response shape and cache state, preventing the ad hoc routing failures seen here.

2. **Constrain identity and schema mechanically.** Supply allowed inventory IDs separately from generated layout IDs. Mapping validation already runs before publication; correct the prompt that permits generated-heading exclusions rejected by that validator. Keep template-owned headings in the shared templates. Preserve all real inventory mappings; never silently discard unknown IDs. Offer a small targeted repair request with the failing IDs and surrounding nodes instead of regenerating an entire page. Repairs are immutable attempts, record every replacement/removal reason and must pass full validation again. Test this against the 18 preserved failures. Broader deterministic ID/provenance generation remains a later extension.

3. **Reduce generated repetition.** Introduce an internal authoring format that references a shared native diagram base plus explicit per-occurrence marks/labels, then materialises ordinary editable project content. Preserve unique occurrence IDs, editable results, source references and independent checks. Base geometry and answer annotations must share a coordinate frame; separately scaled SVG layers caused failures in this import. Avoid a public-schema change unless needed. Use deterministic templates for repeated response grids and scaffolds while preserving source arrangements.

4. **Provide a compact, lossless authoring projection of the inventory.** Keep the complete independent inventory immutable for reconciliation. Send the author every relevant stem, given, diagram specification, response, arrangement, supplied answer and ambiguity, with parent references instead of repeated prose. Remove only repeated bookkeeping and duplicate text already referenced unambiguously. Supply DOCX evidence by relevant source region with reliable fallback to full context. Preserve necessary teaching methods and source images. Benchmark fidelity before adopting; simply truncating prompts would be unsafe.

5. **Extend dependency-aware work queues.** Approved pages already proceed while other pages are blocked, with concurrency 3. Extend this to overlapping inventory/source-only review and approved-topic authoring. Submit immutable generation results to a single publication queue; reject only affected stale dependencies. Preserve revision/conflict protection. More workers are not the first remedy and would need an explicit benchmark and authorisation under current agent rules.

6. **Automate visual-review bookkeeping.** Build a persistent source/render review queue keyed by project, renderer, asset and full-page image hashes. Present unreviewed or changed pages and neighbours directly; persist actual review immediately. Reuse checks during development, or resume actual visual inspection of the same settled result with valid dependencies. Content changes and re-settlement require complete visual inspection again, including pixel-identical pages, under the current acceptance contract. Continue to inspect every page of all five final editions. Do not replace inspection with hashes, counts, contact sheets alone or overflow checks.

7. **Repair observability and preflight.** Persist attempt/phase start events and record available metrics in a finally path for every model call, separating generation, validation, canonical publication and workflow registration outcomes. Unfinished attempts remain visible after abrupt termination. Record phase start/end, concurrency, queue wait, compile/cache hit counts, render duration and review duration. Generate receipts from events rather than manually maintained snapshots. Preflight Windows commands, tool/auth availability, supported TikZ libraries and browser routes before a long run.

## Recommended first implementation package

Start with priorities 7, 2 and 1: minimal reliable metrics, constrained mapping/targeted repair, then integrated final-size diagram preflight. They address observed defects directly without changing the final booklet schema or weakening review gates. The approved correction-chain replay fix from this import is already implemented and covered by regression tests. See the implemented tools and boundaries below; broader improvements remain proposals.

Then evaluate internal shared-diagram authoring and compact inventory projections. DOCX retrieval already supplies excerpts with full-evidence fallback; improve evidence selection rather than introducing a second retrieval path. Token reductions should first be tested against repeated output and avoidable calls. The observed 60% input-cache share is useful context, but does not establish the relative latency or cost benefit of the proposed changes.

## First package: implemented tools

- `semantic-packets.mjs` persists immutable `generation.json` and `task-input.json` before semantic validation, plus append-only `attempt-events.jsonl` with generation/validation/publication/registration phases. Its generated `attempt-receipt.json` covers instrumented attempts only; historical missing usage is not reconstructed. `metrics --run-id RUN` reads events without a model call or writes and reports unfinished attempts. The existing ledger remains compatible and now retains available usage on post-generation failures.
- After an unknown-mapping failure, use `author --run-id RUN --pages PAGE --config CONFIG --attempt 2 --repair-from 1` (choose the actual newer/source attempt numbers). The one bounded repair call receives allowed entries, source groups, invalid mappings and target context. Only invalid mappings can change, and each needs an exact-original record and reason. Content and real mappings remain intact; full semantic/geometry checks and current-input/conflict guards still apply. Historical attempts without a current input snapshot need ordinary reviewed reauthoring; the offline replay command below does not publish them.
- `check-compact-exercises.mjs --diagram-preflight --project ID --project-file CANDIDATE.json --out .booklet-work/RUN/preflight` loads the candidate through read-only project and `/open` routes. It requires `student`, `short` and `worked` compositions, preserves their real widths, and exports PDFs, page PNGs and measurements. It reports complete-label clipping/size, possible overlaps, separate overlay layers, source hashes and stale answer-width overrides. Source comparison and visual review remain explicitly pending. Raster labels, mathematical angle regions and overlay alignment require inspection. Use a small assembled representative candidate before bulk authoring; missing teaching/arrangement context must still be resolved through review-first gates.
- Label-bounds inspection also runs in ordinary development/final compact checks. Preflight outputs never populate final verification manifests or visual acceptance. Browser cache state retains IndexedDB; preflight reports actual TikZ counters and render/export timings, without claiming every compile was fresh or all prior cache entries were reused.
- `replay-mapping-failures.mjs --run-dir RUN --out .booklet-work/REPLAY.json` tests preserved unknown-ID failures offline with explicit diagnostic removals. It never publishes packets or changes source evidence. Angle Relationships replay covers 18 failures: 17 become schema-valid; page 43 retains a separate missing-target defect. All content and real mappings remain unchanged. This is validation evidence, not measured model repair success or source acceptance.

Subsequent packages added the opt-in shared-diagram experiment and the dependency, publication, visual-review and observability tools below. Experimental representations are not default authoring changes.

Implementation validation: 45 focused tests and the production build passed. An isolated four-block candidate rendered 46 native figure occurrences over 11 question/short/worked pages; automated checks passed and all page images were inspected. A second run verified IndexedDB cache-state loading and produced pixel-identical page PNGs. This is tooling validation, not renewed source acceptance or a savings benchmark. Evidence and actual timings are in `.booklet-work/efficiency-implementation-20260913/implementation-receipt.json`. `repo:check` reports two existing DOCX size-limit failures caused by the unfinished indexed source-path move; that separate work is untouched. Concurrent live Angle Relationships layout revisions were also left untouched.

## Second package: opt-in shared diagrams and an offline benchmark

Add `"authoringFormat": "shared-diagrams-v1"` to an isolated run's author config to try the internal format. The standard format remains the default. Inventory generation, source images, teaching context, corrections, project/bank schema and acceptance gates are unchanged. Existing runs are not migrated; changing the author format changes its input/cache signature and requires a new immutable attempt where applicable.

The author may include `authoringFormat: "shared-diagrams-v1"` and a page-local `diagramLibrary` mapping fragment IDs to literal TikZ strings. Each native diagram keeps its own ID, role, widths, spec and source references, and may replace `code` with `codeParts`, an ordered list of fragment-ID strings and `{text: "literal source"}` objects. Parts concatenate exactly without inserted whitespace. For example, a question figure can reference `["base", "end"]` while its separate complete solution figure uses `["base", {"text": "solution marks and labels"}, "end"]`. The actual fragments must form valid TikZ; this example describes the representation, not executable geometry.

`shared-diagram-authoring.mjs` expands every referenced occurrence to one complete `tikzpicture` before semantic and numerical validation. It rejects unknown fragments, recursive definitions, simultaneous `code`/`codeParts`, incomplete/nested pictures and separately scaled `overlayOf`/`solution-overlay` references. Ordinary complete `code` strings remain supported, including within opt-in packets. Raw generation is retained in `generation.json`, expanded output in `materialized.json`, and only normal editable code reaches canonical packets and assembly. Mapping repairs consume expanded content without modifying the original generation. Input hashes bind the materializer implementation; attempt events record format and generated/expanded character counts alongside actual available model usage.

The offline benchmark is repeatable without model calls or project writes:

```text
node scripts/booklet/benchmark-shared-authoring.mjs --run-dir .booklet-work/full-imports/angle-relationships-v1-20260912 --out .booklet-work/RUN/shared-authoring-benchmark.json
```

On the 79 preserved Angle Relationships author packets, conservative factoring of identical contiguous code lines reduced compact JSON from **2,569,235 to 2,465,105 characters (4.05%)**. Seventy-three pages contained reusable fragments. Expansion preserved every packet field and all **863 diagram code strings exactly**; every expanded packet passed semantic validation. Page 7's reduction was 16.32%. These are representation measurements on existing output, not demonstrated model-token, latency, cost or first-pass-fidelity savings. The opt-in instructions also add input characters, reported by the benchmark. No default adoption is justified by this result alone.

The same benchmark tested an exact repeated-text inventory dictionary while retaining every field, given, response, ambiguity and arrangement. All inventories round-tripped, but net potential savings were only **5,320 of 1,477,323 characters (0.36%)**, before decoding instructions. The production inventory prompt remains unchanged; this result does not rule out a future semantic projection with separately demonstrated fidelity.

Validation: **52 focused tests passed**, including native TikZ compilation, unchanged question/answer separation, expanded-output caching, bounded mapping repair, and rejection of an 80° construction against a reviewed 100° inventory. The final offline benchmark took 352 ms and added-format instructions measured 1,272 characters. These timings describe this local benchmark only. Reports and actual check durations are retained under `.booklet-work/efficiency-shared-diagrams-20260913/`; no source packets or live projects were published or edited by the experiment.

Shared diagrams remain opt-in until a generation trial measures actual usage, defects and repairs. Complete source, mathematical, teaching/arrangement and five-edition final visual acceptance remain mandatory for any new booklet.

## Completed workflow integration

`run-workflow.mjs` provides `preflight`, `status`, `drain` and event-derived `receipt` commands. `drain` fills the configured concurrency limit from currently runnable inventory/author tasks and reevaluates dependencies after each completion. Mathematical and representative-pattern decisions remain explicit through `review-workflow.mjs`; blocked pages do not stop independent work. Once no tasks can run, it reports the reasons and exits. Rerunning resumes valid cached results; `--retry` explicitly permits one new immutable attempt per failed/stale stage and page. A failed publication registration can resume from cached output without another generation. Status derives one workflow snapshot per scheduling pass; publication checks a fresh snapshot.

Generation remains concurrent. Canonical publication and workflow registration share a per-run exclusive lock, including across CLI processes. Source, correction, review and canonical-file guards run after acquiring that lock. Queue wait, publication and registration are separate recorded phases. A busy or abandoned lock is never stolen automatically. Valid immutable generation survives a stale-dependency rejection.

`visual-review.mjs` provides `describe`, `prepare`, `status`, `begin`, `record`, `cancel` and `final-record`. The queue binds source evidence, project, renderer, referenced assets, PDF, manifests and full-page images. It saves each actual inspection immediately and resumes pending pages. Development changes invalidate affected physical pages and neighbours; a new final project or settlement requires inspection of every page again, even when pixels match. The normal full exporter now retains individual full-page PNGs alongside its PDF/manifests; valid evidence is reused on subsequent checks. Preflight manifests can only create development queues. `final-record` requires all five editions and every page accepted, then emits input for the existing final acceptance command. It does not grant acceptance itself. Source/image/inspection dependencies are retained in the final register so later edits invalidate the record. See the [command and record examples](booklet-review-first-workflow.md#resumable-run-and-visual-review-tools).

Common append-only run events cover preflight, dependency scheduling, assembly, export and explicit visual-review sessions. Receipts combine these with model-attempt events and take the union of completed time intervals, rather than summing concurrent durations. Canceled and unfinished review sessions receive no completed inspection credit. Render reports retain actual cache/compile counters and per-edition durations; review pauses require ending/canceling the active session. Historical missing usage and unrecorded work remain unavailable. These measurements are not proof of speed or token savings.

Environment preflight checks the configured model policy, every pinned run evidence file, Node/Codex/PDF commands, authentication availability, representative bundled TikZ libraries, and the read-only project/open browser contract. It never generates content, changes authentication or stores authentication identity/output. The real local check verified all 163 pinned files and passed the tool, engine and browser checks; the sandboxed process could not resolve its home directory for the authentication probe. Live model-generation benchmarking therefore remains unverified.

The remaining speculative changes have an explicit disposition: retain the existing deterministic assembly ownership of source-page references, wrapper metadata and teaching-header/grid/scaffold templates; do not introduce a second source of IDs or guess source response dimensions. Retain full independent inventories and the existing DOCX excerpt/full-context fallback. The measured 0.36% inventory dictionary reduction does not justify another production representation. These are intentionally rejected default changes, not unfinished implementation steps.

Local validation and actual timings are in `.booklet-work/efficiency-end-to-end-20260913/implementation-receipt.json`. All **97 regression tests passed** in 8,082.65 ms. The isolated four-block candidate passed all five compositions (27 physical pages, 108 native diagram occurrences, no automated findings) in 27,886 ms, with five full-page source comparisons recorded as a development smoke review and successfully resumed. The other candidate pages are not marked visually accepted, and no final booklet acceptance was created. Regression fixtures separately exercise complete queue-to-final-acceptance handoff, invalidation, concurrency, interrupted work, explicit retries and review gates. Live project edits and original semantic/source evidence were preserved. `repo:check` still reports the two pre-existing indexed Linear Relationships DOCX size-limit errors associated with the separate, unstaged source moves.

## Benchmark and acceptance

Replay preserved Angle Relationships failures and representative source packets in isolated candidate runs; do not modify the accepted project. Cover dense naming grids, cloze teaching, transversals, auxiliary constructions, algebra, source corrections and Challenge illustrations. Follow with the next complete booklet under unchanged acceptance rules.

Compare first-pass validity, missing/altered source content, mathematical and visual defects, calls requiring repair, uncached/cached input, output, active wall time, compilation/cache costs, and review minutes. Define benchmark active elapsed time as the union of recorded work intervals (generation, repair, compilation, export and actual review), excluding decision waits/pauses and counting overlapping work once; report total calendar span separately. Runner-only active time is a narrower metric and cannot stand in for this benchmark. Distinguish call-hours from wall time. Treat 25–40% less active elapsed time and 30–50% less model output as provisional hypotheses to test, not measured savings or delivery promises. Preserve model capability initially so workflow improvements can be measured independently of model changes.

Independent inventory, complete mathematical checking, teaching/arrangement fidelity, editor save/reopen, revision-safe bank transactions, and the complete five-edition visual-review gate remain mandatory.
